ДАННЫЕ И ОГРАНИЧЕНИЯ
Данные хранятся в браузере устройства, без облачной синхронизации. Журнал связывает имена и места текстом: переименование листа не изменит старые записи. Ссылки городов основаны на буквальных упоминаниях. Мастерские заметки не защищены паролем и видны пользователям устройства; JSON-архив тоже содержит их, а также возможные портреты. Восстановление полной копии заменяет коллекцию и заметки. Сначала скачивайте копию.

УСТАНОВКА ЧЕРЕЗ GIT (рекомендуется)
1. Сохраните текущий репозиторий и убедитесь, что нет несохранённых изменений.
2. В корне репозитория создайте ветку: git switch -c companion-update
3. Скачайте файл katarsis-update.patch отдельно, затем выполните:
   git apply --check /ПУТЬ/katarsis-update.patch
   git apply /ПУТЬ/katarsis-update.patch
4. Проверьте изменения: git status, npm install, npm test, npm start.
5. Откройте /play/ и проверьте поиск, создание записей и архивирование.
6. Зафиксируйте и отправьте ветку, откройте pull request и после проверки объедините с основной веткой. Публикация зависит от настроек Cloudflare проекта.

УСТАНОВКА ЧЕРЕЗ САЙТ GITHUB БЕЗ GIT
1. Распакуйте архив, НЕ загружайте сам архив как файл репозитория.
2. Создайте ветку для обновления. По очереди откройте на GitHub папки web, web/play, src, scripts и tests; для каждой выберите Add file → Upload files и загрузите файлы из соответствующей папки архива, подтвердив замену существующих файлов. Важно сохранить пути и имена, не загружать всё в корень.
3. Перечень файлов:
   web/companion.js                       новый
   web/companion.css                      новый
   web/play/index.html                    замена
   src/worker.mjs                         замена
   scripts/prepare-assets.mjs             замена
   scripts/prepare-materials.mjs          замена
   scripts/update-from-html.py            замена
   tests/companion-browser-check.mjs       новый
4. Проверьте ветку, затем создайте pull request и объедините. НЕ заменяйте весь репозиторий содержимым архива: в архиве только изменения.

ПРОВЕРКА
В этой среде прошли npm test (20 тестов), существующие браузерные тесты персонажей и игровых инструментов, а также новый браузерный тест поиска, заметок, очереди ходов, полного экспорта/импорта, отказа повреждённому файлу, подсказок и мобильной ширины. Для ручного запуска browser-check нужен отдельно установленный Playwright и Chromium; зависимости самого сайта не менялись.

Сборка npm start / npm run prepare:materials проверена. update-from-html.py сохранит подключение новых файлов при пересборке, однако исходный большой HTML и опубликованный play/index.html в репозитории имеют разные контрольные суммы сборки: не запускайте полную пересборку без отдельной проверки её результата. Обычный npm start и npm run deploy запускают prepare:materials, а не update-from-html.py.
